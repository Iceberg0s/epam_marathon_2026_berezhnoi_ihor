# Green & Tasty — вебзастосунок ресторану та групове попереднє замовлення

Green & Tasty — вебзастосунок для бронювання столиків і попереднього замовлення страв. Власник бронювання може запросити гостей, які додають страви до власних кошиків. Перед надсиланням система об’єднує замовлення учасників.

## Архітектура та технології

Застосунок складається з Angular SPA та безсерверного backend, розгорнутого в AWS (регіон `us-west-2`).

- **Backend:** C# / .NET 10 у AWS Lambda (`api-handler`).
- **API та авторизація:** AWS API Gateway і Amazon Cognito.
- **База даних:** Amazon DynamoDB; дані охоплюють локації, столики, бронювання, групові бронювання, гостьові сесії, страви, замовлення, офіціантів і відгуки.
- **Frontend:** Angular 22 із standalone-компонентами, signals та реактивним керуванням станом.
- **Хостинг frontend:** AWS S3 та Amazon CloudFront.
- **Синхронізація групового замовлення:** сторінка власника оновлює дані учасників приблизно кожні 15 секунд.

## Основні можливості

### Клієнтський застосунок

- **Бронювання столика:** пошук і бронювання за локацією, датою, часом і кількістю гостей.
- **Особисте попереднє замовлення:** додавання страв у кошик до відвідування ресторану.
- **Групове попереднє замовлення:**
  - Власник бронювання створює запрошення для гостей.
  - Гості відкривають посилання `/join/{token}`, вводять ім’я та формують власні кошики без створення облікового запису.
  - Власник переглядає учасників, страви, суми й статуси надсилання на сторінці `/reservations/{id}/group-order`.
  - Після надсилання кошики учасників об’єднуються: однакові страви консолідуються з підсумованою кількістю та додаються до замовлення ресторану.
  - Власник може видаляти учасників; підсумок перераховується.

## Локальний запуск frontend

Потрібен Node.js версії, зазначеної у `frontend/restaurant-frontend-app/.nvmrc` (зараз `24.16.0`).

```bash
cd frontend/restaurant-frontend-app
npm ci
npm start
```

Відкрийте <http://localhost:4200>. Локальний frontend використовує API URL, заданий у файлі середовища для розробки.

### Production-збірка frontend

Production-збірка потребує змінної `BACKEND_URL`. У PowerShell:

```powershell
cd frontend\restaurant-frontend-app
$env:BACKEND_URL = 'https://<ваш-api-id>.execute-api.us-west-2.amazonaws.com/develop'
npm run build
```

Збірка створюється в `dist/restaurant-frontend-app/browser`. Публікація статичних файлів в S3 та очищення кешу CloudFront виконуються окремо.

## Backend та розгортання

Для backend потрібен .NET 10 SDK. API-обробники розташовані в `backend/restaurant-backend-app/dnapp/lambdas/api-handler`.

Backend розгортається в AWS за допомогою AWS Syndicate. Для розгортання потрібні AWS CLI з доступом до цільового AWS-акаунта та локальна конфігурація Syndicate; конфігурація з обліковими даними не зберігається в репозиторії. Перед deployment перевірте цільовий AWS-акаунт, регіон і набір ресурсів.

Документація API: [backend/restaurant-backend-app/docs/ApiRoutes.md](backend/restaurant-backend-app/docs/ApiRoutes.md).

## Автоматизовані тести

### Backend

З кореня backend-проєкту:

```powershell
cd backend\restaurant-backend-app
dotnet test
```

### API та end-to-end тести

Додано API-тести для сценаріїв групового замовлення рівнів 1–3: перегляд учасників і сум, консолідація замовлення та видалення учасника. Також є базові Playwright UI-перевірки головної сторінки, меню та відкриття гостьового запрошення.

AQA набір ще не підтверджений повним запуском на окремому тестовому середовищі. UI-сценарій власника від створення групового замовлення до submit і перевірки результату в інтерфейсі офіціанта ще потрібно додати. До такого запуску не вважати рівні повністю пройденими.

Тести створюють тестові облікові записи та дані в API. Запускайте їх лише проти ізольованого тестового середовища; локальний `.env` не комітьте.
